# HapticsLab

Use Xcode MCP for source, resource, project changes, Apple documentation, builds, and simulator verification. Stop code work and report unavailable MCP operations. Review SwiftUI changes using relevant Xcode skill guidance; distinguish locally exposed built-in skills from external exported copies.

Preserve iOS 26.0, Swift 6, SwiftUI, native Apple frameworks, and zero third-party dependencies. Keep native UI objects and observable state on MainActor, configuration Sendable, and asynchronous playback protected against stale callbacks. Do not suppress isolation checking.

Run focused unit/UI tests after changes and finish with a normal build. Simulator tests verify requests and UI, never physical vibration. Report unexecuted hardware and minimum-runtime checks. Do not install on physical devices or change repository visibility without an explicit request.

Keep personal signing settings, credentials, build output, and Xcode user state out of Git. See README.md and VERIFICATION.md.
